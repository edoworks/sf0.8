# Adaptive Runner Investment Decision

Date: `2026-09-23`

Status: `BOUNDED_EXPERIMENT_ONLY`

Research package: [adaptive runner](../research/adaptive-runner/README.md)

Map: [issue #135](https://github.com/edoworks/sf0.8/issues/135)

## Decision

Foculoom should not begin the adaptive endless-runner product or revive Skiplet.
It should authorize only the E0 movement bake-off specified in
[ROADMAP.md](../research/adaptive-runner/ROADMAP.md), subject to a reviewed E0
`PREREGISTRATION` record before prototype implementation begins.

The adaptive thesis remains unproven and is downstream of four earlier gates:
Fun, Replayability, Retention, and Variety. Generative AI is downstream of the
Personalization gate and must beat a deterministic adaptive director.

## Evidence-Based Root-Cause Analysis Of Prior Quality Failure

Observed defect: prior implementations did not meet the founder's quality bar,
and the founder's child lost interest after several minutes.

1. Why did additional implementation not resolve the product problem? Prior
   builds accumulated movement, levels, missions, achievements, worlds,
   collectibles, and progression without evidence that movement alone earned
   voluntary replay.
2. Why could feature breadth advance without that evidence? Technical completion
   and broad feature prompts preceded a binding behavioral fun gate.
3. Why was the behavioral gate not durable? Skiplet's validation plan remained a
   draft, while the runner template's declared canonical PRD and validation files
   are missing.
4. Why did documentation state and implementation state diverge? The surviving
   repository contract references absent artifacts, so no mechanically enforced
   source linked product hypotheses to phase advancement.
5. Evidence stops here. The available records do not establish a deeper human,
   process, or model-specific cause and do not support blaming any one AI model.

Immediate correction: stop feature expansion and run E0. Root-cause correction:
make behavioral gates dependencies for every later phase. Mechanical recurrence
guard: the package defines a machine-readable phase-gate schema and requires a
future canonical product repository to fail Phase N+1 transitions without a
reviewed Phase N `PASS`. That CI guard is specified but not active because no
product repository or implementation phase is authorized yet; claiming current
enforcement would overstate the evidence.

## Scope

- Three disposable movement candidates.
- Fixed authored courses, deterministic replay, equal placeholder presentation,
  basic accessibility, neutral audio/haptics, and consented observation.
- One targeted revision maximum if all candidates fail.

## Out Of Scope

Product naming, Skiplet revival, progression, procedural generation, player
model, adaptation, Foundation Models, final art, monetization implementation,
App Store work, and public claims.
